About this site

occamlang.org (also at occam-lang.org) aims to be the main home on the web for occam, CSP and the transputer tradition. It picks up where WoTUG left off.

Why

occam's ideas are more relevant now than when it was designed. Mainstream languages have adopted channels, lightweight processes and message passing, but the material explaining where those ideas came from, and how far occam took them, is scattered across failing servers. This site gathers it, keeps it working, and teaches the language with programs that run today.

The design
  • Type. Inmos manuals and technical notes were set in Helvetica. The site uses it where your system has it, falling back to a close grotesque.
  • Folds. Every section, and many code listings, are folds in the style of the Inmos TDS: ... when closed, {{{ and }}} when open.
  • Process diagrams. Networks are drawn as Peter Welch drew them, as boxes for processes and arrows for channels. Networks nest, and you can open them like folds.
  • Lecture-note listings. The SEQ/seq switch in the header shows code in the handwritten style of occam teaching, with lower-case, underlined keywords.

Contributing

Contributions are very welcome, especially:

  • Papers and documents that are not yet online: WoTUG/OUG proceedings, Inmos technical notes, theses, course notes;
  • Examples: well-commented occam programs with a process diagram;
  • Corrections: dates, attributions, broken links;
  • Tooling: help with the in-browser playground and a modern build of SPoC.

The site is plain HTML, CSS and JavaScript with a small dependency-free build script. Archive entries are one JavaScript data file, so adding a paper is a one-line change. The source is at github.com/jimmoores/occamlang. Issues and pull requests are welcome.

For anything else, including offers of papers or documents, email jim.moores@gmail.com.
