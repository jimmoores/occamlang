Communicating Sequential Processes

Parallel programs, made simple.

occam is a small, exact language for building systems out of processes that share nothing and talk over channels. Designed at Inmos with Hoare's CSP as its mathematical basis, it ran the transputer, inspired Go and XMOS, and still compiles and runs today.

The idea

Processes, channels, and nothing shared

An occam program is a network of processes. Each process has private state. Processes interact only by passing messages over channels, and a channel communication happens only when both sender and receiver are ready. There are no locks, no shared variables and no data races, and the compiler checks those rules for you.

Because the language maps directly onto Hoare's CSP algebra, an occam program can be reasoned about, transformed and model-checked. The same design worked on one chip, on a thousand-transputer machine and, compiled to gates, on an FPGA.

Run it today

occam is not a museum piece

Razor is an actively maintained fork of the Kent Retargetable occam Compiler. It brings occam-π to current 64-bit systems. SPoC, the Southampton Portable occam Compiler, translates occam 2 to portable C.

We also plan to run occam in your browser, so every example on this site can be edited and run in place.
