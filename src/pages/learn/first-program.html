Line by line:

  • #INCLUDE "course.module" brings in KRoC's teaching library, which has out.string, out.int and friends.
  • A program is a PROC. Its parameter is a channel of bytes, out. The ! says this process writes to it. The run-time connects it to standard output.
  • out.string (s, field, out!) sends each byte of s down out. *n is occam's newline escape (occam uses * where C uses \).
  • A lone : ends the declaration. Every declaration in occam, whether a variable, channel or PROC, ends with a colon.

Layout is syntax

occam has no braces and no begin/end. Indentation of exactly two spaces shows that a process is part of the construct above it. Every construct (SEQ, PAR, IF, WHILE, ALT) is a keyword on its own line with its components indented beneath it:

SEQ
  x := 1
  y := x + 1
  out ! y

This is why occam fits folding editors so well: every indented block is a complete process and can be folded away as a unit.

Declarations come immediately before the process they belong to, and their scope is that process:

INT x, y:          -- two integers, in scope for the SEQ below
SEQ
  x := 6
  y := x * 7

SEQ, IF and WHILE

A program that prints a times table:

VAL INT n IS 7: declares a named constant. SEQ i = 1 FOR 12 is a replicator: it runs its body 12 times with i counting from 1. Replicators also work with PAR, IF and ALT.

IF tests its conditions in order and runs the process under the first one that is true:

IF
  x < 0
    sign := -1
  x = 0
    sign := 0
  TRUE
    sign := 1
Watch out. If no condition in an IF is true, the IF behaves like STOP, and the process stops forever. This is deliberate: occam never silently ignores a case you did not handle. Finish with TRUE / SKIP if doing nothing is really what you want.

WHILE is the only loop:

INT a, b:
SEQ
  a, b := 1071, 462       -- multiple assignment
  WHILE b <> 0
    a, b := b, a \ b      -- \ is remainder
  out.int (a, 0, out!)    -- gcd = 21

Types in brief

INT, INT16, INT32, INT64, BYTE, BOOL, REAL32, REAL64, and arrays such as [10]INT. There are no implicit conversions: write REAL64 ROUND n or INT TRUNC x. Arithmetic with +, -, * is checked, so overflow is a run-time error. PLUS, MINUS and TIMES wrap around silently. Operators have no precedence, so mixed expressions must be bracketed: (a + b) * c.
