Lesson 4 of 4

Choice & time

ALT lets a process wait for whichever of several things happens first. With TIMER it can also react to time passing.

ALT

An ALT lists guarded alternatives. It waits until at least one guard is ready, chooses one, and runs the process under it. A multiplexer that merges two streams is:

PROC mux (CHAN INT in.0?, in.1?, out!)
  WHILE TRUE
    INT x:
    ALT
      in.0 ? x
        out ! x
      in.1 ? x
        out ! x
:

The input in the guard happens first, and then the indented process runs. If both inputs are ready, ALT picks one; the language does not say which. That matches CSP's external choice, □.

Boolean guards

A guard can have a condition attached with &. The alternative is only considered while the condition is true. A bounded buffer only accepts input while there is room and only offers output while it has something to give:

PROC buffer (VAL INT max, CHAN INT in?, request?, out!)
  {{{! state: a circular queue
  [64]INT q:
  INT head, count:
  }}}
  SEQ
    head, count := 0, 0
    WHILE TRUE
      ALT
        (count < max) & in ? q[(head + count) \ max]
          count := count + 1
        INT any:
        (count > 0) & request ? any
          SEQ
            out ! q[head]
            head, count := (head + 1) \ max, count - 1
:

Note the INT any: declaration placed just before the second guard. It is in scope only for that alternative. (max must be at most 64 here.)

PRI ALT

PRI ALT gives earlier guards priority when several are ready. Here it is used to make a reset signal always take effect before more data:

PROC integrate.reset (CHAN INT in?, reset?, out!)
  INT total:
  SEQ
    total := 0
    WHILE TRUE
      PRI ALT
        INT any:
        reset ? any
          total := 0
        INT x:
        in ? x
          SEQ
            total := total PLUS x
            out ! total
:

Compare it with Legoland's integrate. The network version was easier to reason about but could not be reset. This one keeps its state in a variable, so a single process can respond to control signals. Both styles are good occam; choose the one that fits the job.

Replicated ALT

An ALT can be replicated over an array of channels. This is how a server listens to any number of clients:

PROC collect ([]CHAN INT in?, CHAN INT out!)
  WHILE TRUE
    ALT i = 0 FOR SIZE in
      INT x:
      in[i] ? x
        out ! x
:

Time

A TIMER is a clock you can read like a channel: tim ? t. Its units depend on the platform (microseconds in KRoC and Razor). tim ? AFTER t waits until the clock passes t. Use PLUS for time arithmetic, because the clock wraps around. A process that ticks at a steady rate:

PROC ticker (VAL INT period, CHAN INT out!)
  TIMER tim:
  INT t, n:
  SEQ
    n := 0
    tim ? t
    WHILE TRUE
      SEQ
        t := t PLUS period
        tim ? AFTER t          -- sleep until the next tick
        out ! n
        n := n + 1
:

As an ALT guard, AFTER gives a timeout:

TIMER tim:
INT now, x:
SEQ
  tim ? now
  ALT
    in ? x
      out.string ("got a value*n", 0, screen!)
    tim ? AFTER now PLUS 1000000        -- one second
      out.string ("timed out*n", 0, screen!)
Exercise: a stoppable counter Write PROC counter (CHAN BOOL pause?, CHAN INT out!) that outputs 0, 1, 2, … one per 100 ms, and stops or restarts each time a value arrives on pause. You will need a PRI ALT, a TIMER guard and a BOOL guard condition.
